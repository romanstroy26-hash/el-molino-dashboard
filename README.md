# El Molino -- система аналитики

Цель всего проекта: постепенно собрать маленькие независимые блоки на
Python, из которых складывается дашборд (пункт "Фаза 1" дорожной карты).
Каждый блок делает одну вещь и не знает о существовании других:

```
tiempo.py              -- время: ВСЯ программа живёт по Сан-Луис-Потоси
extractors/wansoft.py  -- читает файл Wansoft -> отдаёт "чистые" строки
db.py                  -- знает про базу данных (SQLite локально ИЛИ Postgres в облаке)
metrics.py              -- считает доли/декады/год-к-году + распознаёт "что такое кофе"
etl_load.py             -- склеивает: файлы -> extractors -> db
correo.py                -- забирает отчёты Wansoft из почты
auto_carga.py            -- сама находит новые выгрузки и грузит их
menu.py                  -- меню в командной строке (загрузка файлов)
dashboard.py             -- ОДИН файл: интерфейс с графиками и формой настроек
limpiar_duplicados.py    -- разовая уборка задвоенных чеков в старой базе
```

## Быстрый старт

1. Скопируй файл(ы) выгрузки из Wansoft ("Reporte Detalle De Ventas
   ....xlsx") в папку `data` рядом со скриптами (если её ещё нет --
   создай сама программа при первом запуске, или создай вручную).
2. Дважды кликни `Start.bat` -- загрузит данные в базу через меню
   (первый раз сам поставит библиотеки, минуту-две).
3. Дважды кликни `Dashboard.bat` -- откроется страница в браузере с
   графиками и фильтрами.

Ещё две кнопки нужны реже:

- `Cleanup.bat` -- один раз, если база собиралась старой версией
  программы (см. "Почему одни и те же дни не задваиваются" ниже);
- `Publish.bat` -- отправить изменения программы в GitHub, чтобы они
  доехали до дашборда в телефоне (см. "Как отправить изменения в
  облачный дашборд").

Все файлы выгрузок (.xlsx) держим в подпапке `data` -- так они не
мешаются среди файлов самой программы. Программа сама туда заглядывает,
ничего указывать не нужно.

Пока рядом нет файла `.env` -- всё работает на локальном файле
`el_molino.db`, ничего настраивать не нужно.

## База данных: локально или в облаке

По умолчанию -- локальный файл `el_molino.db` рядом со скриптами: просто
файл на диске, ничего ставить не надо, но его видит только этот
компьютер.

Чтобы данные лежали в одном месте и были доступны с любого компьютера
(например, из двух точек одновременно) -- переключаемся на облачную
Postgres-базу. Бесплатно, ~5 минут:

1. Зарегистрируйся на [supabase.com](https://supabase.com) (или
   [neon.tech](https://neon.tech) -- тоже подходит).
2. Создай новый проект, придумай пароль для базы.
3. Наверху страницы проекта нажми зелёную кнопку **Connect**.
4. В открывшемся окне будет несколько плиток: Framework, Server, Direct
   Connection, ORM, MCP. Нажми **Direct Connection** (не MCP -- это для
   других ИИ-программ, а не для нашей).
5. Внутри этой вкладки выбери режим **Session pooler** (не "Direct
   connection" -- тот требует IPv6, а на обычном домашнем/офисном
   интернете это редко есть; Session pooler работает везде и бесплатно).
7. Скопируй строку вида
   `postgresql://postgres.xxxxx:[YOUR-PASSWORD]@aws-0-...pooler.supabase.com:5432/postgres`
   и вставь свой пароль вместо `[YOUR-PASSWORD]`.
8. Скопируй файл `.env.example` в этой папке в `.env` (без `.example`) и
   вставь туда эту строку вместо примера.
9. Перезапусти `Start.bat` / `Dashboard.bat` -- дальше все данные (и
   загрузка, и настройки) идут уже в облако.

Больше НИЧЕГО менять не нужно -- ни в `extractors/`, ни в `metrics.py`,
ни в `dashboard.py`: все они обращаются к базе только через `db.py`, а
он сам решает, локальный это файл или облако, по наличию `.env`. Это и
есть та самая "адаптация под любую базу", ради которой всё с самого
начала разложено по отдельным блокам.

Проверено в этом разговоре на двух движках по-настоящему (не только в
теории): SQLite и Postgres 16 -- одни и те же данные, один и тот же
результат на выходе.

## Смотреть дашборд с телефона (из любого места)

Обычный запуск через `Dashboard.bat` поднимает дашборд только на этом
компьютере: с телефона его видно, если он в той же Wi-Fi сети, и только
пока компьютер включён и программа запущена.

Чтобы дашборд был доступен всегда -- с любого телефона, из кафе, из
дома, даже когда этот компьютер выключен -- один раз (~15-20 минут)
размещаем его в бесплатном облачном хостинге **Streamlit Community
Cloud**. Ничего в самой программе не меняется -- облако просто
запускает тот же `dashboard.py`, но читает данные уже из облачной базы,
а не с этого диска. Поэтому предыдущий раздел (**База данных: локально
или в облаке**) -- обязательное условие: без него компьютер с локальным
`el_molino.db` из интернета не виден никак.

Порядок разовой настройки:

1. Сначала сделай раздел выше -- переключись на Supabase/Neon и
   убедись, что `Dashboard.bat` на этом компьютере уже показывает
   данные из облака (в подписи наверху дашборда будет "облако", а не
   "локальный файл").
2. Зарегистрируйся на [github.com](https://github.com) (если ещё нет
   аккаунта) и создай новый **приватный** репозиторий (кнопка **New**
   -> Private), например `el-molino-dashboard`.
3. Загрузи туда все файлы этой папки, КРОМЕ `.env` и `el_molino.db` --
   в них пароль от базы и локальные данные, им в GitHub не место.
   Проще всего через [GitHub Desktop](https://desktop.github.com) --
   он не потребует команд в консоли. Файл `.gitignore` в этой папке уже
   настроен так, чтобы `.env` и `el_molino.db` не попали в репозиторий
   по ошибке.
4. Зарегистрируйся на [share.streamlit.io](https://share.streamlit.io)
   (тоже бесплатно, войти можно тем же аккаунтом GitHub).
5. Нажми **Create app** -> **Deploy a public app from GitHub**, выбери
   свой репозиторий, ветку `main` и файл `dashboard.py`.
6. Перед запуском разверни **Advanced settings** -> вкладка **Secrets**
   и вставь туда ту же строку, что и в свой `.env` на шаге 1:
   ```
   DATABASE_URL = "postgresql://postgres.xxxxx:[пароль]@aws-0-...pooler.supabase.com:5432/postgres"
   ```
   Это облачный аналог файла `.env` -- пароль от базы никогда не
   попадает в код на GitHub.
7. Нажми **Deploy** и подожди пару минут -- Streamlit сам поставит
   библиотеки из `requirements.txt` и откроет дашборд по адресу вида
   `https://el-molino-dashboard.streamlit.app`.
8. Чтобы дашборд не увидел кто попало по этой ссылке -- в настройках
   приложения (значок **⋮** -> **Settings** -> **Sharing**) сделай его
   приватным и укажи свою почту как единственного зрителя. Это бесплатно,
   но приватным одновременно можно держать только одно такое приложение.
9. Сохрани получившуюся ссылку на телефоне (в закладки или на домашний
   экран) -- она будет работать всегда, независимо от того, включён ли
   этот компьютер.

### Как отправить изменения в облачный дашборд

Важно понимать разделение: **данные** идут в облачную базу напрямую с
этого компьютера (`Start.bat`), а вот **сама программа** в облаке берётся
не с диска, а из GitHub. Поэтому если поменялся код (починили ошибку,
добавили график) -- в телефоне он появится только после отправки в
GitHub.

Для этого -- **дважды кликни `Publish.bat`**. Он:

1. копирует файлы программы в папку репозитория (ту, что завёл GitHub
   Desktop), но БЕЗ `.env`, без `el_molino.db` и без папки `data` -- в
   GitHub уезжает только код;
2. показывает список того, что изменилось;
3. делает коммит и отправляет в GitHub.

Дальше Streamlit Cloud сам замечает отправку и пересобирает дашборд --
обычно 1-3 минуты, ничего нажимать не надо. Потом открой ссылку в
телефоне и нажми "🔄 Обновить данные".

Если изменений нет, кнопка так и скажет и ничего отправлять не станет.
Отдельно входить в GitHub не нужно -- `Publish.bat` пользуется тем же
входом, что и GitHub Desktop. Если вдруг попросит -- открой GitHub
Desktop, нажми там один раз "Push origin", и кнопка снова заработает.

Путь к папке репозитория прописан в первых строках `Publish.bat` (строка
`REPO_DIR`) -- если GitHub Desktop держит её в другом месте, поправь там.

Загружать новые выгрузки Wansoft по-прежнему нужно с этого компьютера
(`Start.bat`) -- как только он переключён на облачную базу (шаг 1),
загруженное сразу попадает в ту же базу, которую читает дашборд в
телефоне. Показывается новое либо сразу при следующем открытии
страницы, либо чуть раньше, если нажать "🔄 Обновить данные" в боковой
панели (кнопка сбрасывает кэш -- см. раздел про скорость ниже).

## Автоматическая загрузка

Чтобы не копировать файлы руками и не открывать меню, есть
`Autoload.bat`. Он сам:

- смотрит в папку "Загрузки" (куда браузер кладёт скачанное из Wansoft),
  в папку `data`, а также в любые свои папки, перечисленные в `.env`
  строкой `CARPETAS_EXTRA` (см. ниже про облачную папку);
- берёт оттуда отчёты "Reporte Detalle De Ventas", а остальные отчёты
  Wansoft ("Ventas por Sucursal", "Por Horario" и прочие) молча
  пропускает -- в них нет нужных колонок;
- грузит всё новое в базу (в ту же, что и `Start.bat`);
- помнит, что уже загружено, и не перечитывает те же файлы заново;
- пишет, что и когда загрузил, в `data\carga.log`.

То есть от тебя остаётся только скачать отчёт из Wansoft -- дальше
ничего нажимать не нужно.

Повторов можно не бояться: загрузка идёт по чекам, поэтому один и тот же
файл, скачанный дважды, или две выгрузки с пересекающимися датами дадут
ровно один результат. Если день загрузился неполным (выгрузку сделали
днём, магазин ещё торговал) -- скачай свежую выгрузку за этот день, и
`Autoload.bat` её подхватит: день достроится, а не задвоится.

### Скачивать не с этого компьютера

Вход в портал Wansoft закрыт защитой от автоматизации (Cloudflare
Turnstile) -- это значит, что скачать отчёт может только человек, руками.
Зато не важно, КТО и ОТКУДА это делает.

Если прописать в `.env` строку

```
CARPETAS_EXTRA=C:\Users\user\Google Drive\El Molino
```

и указать там папку Google Drive или OneDrive, синхронизированную с этим
компьютером, то выгрузку можно скачивать где угодно -- с телефона, из
пекарни, с любого чужого ноутбука -- и просто класть в эту папку. Файл
приедет на компьютер сам, программа его подхватит и загрузит.

Так ежедневное действие сокращается до "скачал и перетащил в папку", и
его может делать кто-то из сотрудников в Мексике, прямо после закрытия --
то есть отчёт будет ещё и за полный день.

Папок можно указать несколько, через точку с запятой.

### Отчёты прямо из почты (чтобы не скачивать вручную)

Wansoft умеет сам присылать отчёт на e-mail по расписанию. Если это
включить, скачивать ничего не нужно вообще: `Autoload.bat` сам заходит в
почту, забирает вложение и грузит его в базу.

Настраивается один раз, в двух местах.

**1. В Wansoft** -- включить отправку отчёта "Detalle de Ventas" на почту
по расписанию (в разделе отчётов -- "envío programado" / отправка по
расписанию). Ставь время ПОСЛЕ закрытия точек, иначе в письмо попадёт
половина дня. И лучше просить отчёт за вчерашний день целиком, а не "с
начала месяца" -- так письма будут меньше.

**2. В файле `.env`** -- дописать пять строк:

```
CORREO_SERVIDOR=imap.gmail.com
CORREO_USUARIO=твой-ящик@gmail.com
CORREO_CLAVE=пароль приложения
CORREO_REMITENTE=wansoft.net
CORREO_CARPETA=INBOX
```

`CORREO_CLAVE` -- это **пароль приложения**, отдельный пароль только для
программ, а не обычный пароль от почты. У Gmail он берётся так: Аккаунт
Google -> Безопасность -> Двухэтапная аутентификация -> Пароли
приложений. Обычный пароль не подойдёт (с двухэтапной защитой он не
работает) и вписывать его не нужно: пароль приложения можно отозвать
одной кнопкой, не трогая основной.

Письмо помечается прочитанным только после того, как вложение успешно
сохранено -- если что-то сорвалось, в следующий раз оно возьмётся снова.
Посторонние вложения (другие отчёты Wansoft, картинки из подписи)
пропускаются.

Проверить отдельно, не дожидаясь расписания: `py correo.py`.

Пока эти строки в `.env` не прописаны, всё работает как раньше -- просто
почтовый шаг пропускается, и файлы берутся из папки "Загрузки".

**Чтобы это происходило само, по расписанию** -- дважды кликни
`Schedule.bat` ОДИН раз. Он создаст в планировщике Windows ежедневную
задачу на 11:00 по времени этого компьютера.

Время выбрано не случайно: 11:00 в Москве -- это около 02:00 в
Сан-Луис-Потоси, то есть вчерашний день в пекарнях уже закрыт и выгрузка
за него полная. Если ставить на вечер по Москве, в Мексике будет середина
дня и в базу ляжет половина дня.

Если компьютер в это время выключен или спит -- задача не потеряется,
Windows выполнит её при ближайшем включении. Но совсем без этого
компьютера она не работает: загрузка идёт с него.

Убрать задачу можно в приложении "Планировщик заданий" (Task Scheduler),
она называется `El Molino - autocarga`.

## Время: всё считается по Сан-Луис-Потоси

Вся программа -- и расчёты, и дашборд -- живёт по времени пекарен
(`America/Mexico_City`), а не по часам того компьютера или сервера, где
она запущена. Это одно правило без исключений, и живёт оно в одном файле
`tiempo.py`; больше нигде в программе текущее время не спрашивается.

Почему это важно: дашборд открывают и с компьютера в Москве, и из
облака (оно работает по UTC), и с телефона. Раньше каждый из них считал
"сегодня" по-своему, и вечером в Мексике это расходилось на целую дату --
пока в пекарне ещё суббота и магазин торгует, для облака уже наступило
воскресенье. Дашборд тогда считал незакрытую субботу закрытой, сравнивал
полдня с полным днём и показывал падение процентов на пятьдесят, которого
не было. Теперь ответ одинаковый с любого устройства.

Текущее время пекарен видно в боковой панели на каждой странице --
строка "🕐 Сан-Луис-Потоси". Если открыть дашборд ночью по Москве, сразу
видно, что там ещё вечер предыдущего дня, и цифры не противоречат друг
другу.

Про переход на летнее время думать не нужно: Мексика его отменила, а
указана не "минус шесть часов", а название зоны -- если правила
когда-нибудь поменяются, программа узнает об этом сама.

## Форма для ручного изменения данных

На странице "Настройки" в дашборде (переключатель слева) есть форма:
список слов, по которым программа узнаёт "это кофе" (американо,
капучино, латте и т.д. -- только среди позиций из групп меню
CAFETERIA/FRAPPES). Можно добавить новое слово, когда в меню появится
новый напиток, или убрать лишнее -- жмёшь "Сохранить", и уже открытый
дашборд сразу пересчитывается по новому списку, даже для старых
загруженных данных. Ничего в коде трогать не нужно.

То же самое можно сделать и без браузера, прямо в `Start.bat` ->
пункт 3 меню.

## Полные продажи (не только кофе)

Кроме доли кофе, дашборд теперь показывает всю картину продаж:

- **"Главная"** -- открывается первой: как прошёл день -- количество
  продаж (чеков), выручка, средний чек, доли по категориям (Panadería /
  Pastelería / Café / остальное), два окна сравнения с прошлой неделей и
  два графика по часам -- выручка и отдельно штуки (сколько единиц
  товара продано), прогноз против факта. По умолчанию --
  последний загруженный день и все точки вместе, но точку и день можно
  поменять в фильтрах слева. Заголовок -- одной строкой: название точки
  (или "Todos El Molino", если выбраны все точки сразу) -- дата без года
  (ДД.ММ) -- день недели. Слева -- все цифры за день, справа, в той же
  строке -- два окна сравнения, всё впритык, без прокрутки страницы.
  - Первое окно ("День к дню") -- ПОСЛЕДНИЙ ЗАКРЫТЫЙ день против ТАКОГО ЖЕ
    дня недели ровно неделю назад (например, пятница против прошлой
    пятницы). Если на странице выбран сегодняшний (ещё не закрытый) день,
    окно всё равно берёт последний закрытый -- скажем, показывает
    пятницу, если сегодня суббота -- и подписывает это прямо в окне.
  - Второе ("Неделя к неделе") -- НЕ календарная неделя (не с
    понедельника), а последние 7 дней, считая назад от последнего
    закрытого дня, против предыдущих 7 дней -- без общих дат: каждый день
    попадает ровно в один из двух периодов. Например, если последний
    закрытый день -- 18.09, сравнивается 12.09-18.09 с 05.09-11.09.
  - В обоих окнах -- и выручка, и количество проданных штук, каждое со
    своей стрелкой (зелёная вверх / красная вниз) и прошлым значением
    рядом, чтобы сразу было видно, выросли или упали обе цифры.
  - "Закрытый день" -- любой день, кроме сегодняшней календарной даты
    (мы работаем постфактум: вчера и раньше уже точно всё закрыто,
    а сегодня магазин ещё может торговать). Сегодняшний день никогда не
    попадает ни в одно из этих двух окон.
- **"Продажи по часам"** -- то же самое, но с выбором любого дня и
  точки: и выручка, и штуки по часам, "Прогноз" против "Факта" (мы ведь
  работаем постфактум, по выгрузкам, а не по живой кассе -- поэтому
  "прогноз" здесь не про будущее, а обоснованное ожидание для такого дня,
  посчитанное из истории).
  - Прогноз строится ТОЛЬКО из дней с ТЕМ ЖЕ днём недели, что и выбранный
    (пятница сравнивается только с прошлыми пятницами и т.д.) и
    использует ВСЮ доступную историю без ограничения по диапазону -- но
    не простым средним, а взвешенным: недавние недели весят больше
    старых (экспоненциальное затухание с полупериодом ~8 недель), поэтому
    прогноз следует за текущим трендом бизнеса, а не тонет в данных
    полугодовой давности; резкие разовые всплески или провалы в отдельный
    час (праздник, банкет навынос, форс-мажор) сглаживаются -- один такой
    день не перекашивает прогноз для всех остальных пятниц.
  - Факт нарисован насыщенной золотой линией, прогноз -- тонкой
    приглушённой линией с лёгкой заливкой под ней, чтобы взгляд сразу
    цеплялся за реальные сегодняшние цифры, а не тонул в двух одинаково
    ярких линиях. Самый важный час (пиковый по факту) подписан числом
    прямо на графике -- главное видно сразу, без наведения мышкой. При
    наведении на график всплывает точное число за любой час.
  - Под графиком -- блок **"Анализ дня"** (и на "Главной", и на "Продажи
    по часам"): короткая справка, насколько день отклонился от прогноза,
    почему, и что с этим делать. Это не ИИ, а несколько прозрачных
    арифметических правил над теми же цифрами, что и на графике (вся
    логика -- в `metrics.analizar_desempeno_por_hora`):
    - если выручка в пределах ±5% от прогноза -- пишет, что день прошёл
      штатно, и на этом всё;
    - если выручка ВЫШЕ прогноза -- хвалит день и предлагает посмотреть,
      что сработало лучше обычного, чтобы повторить;
    - если НИЖЕ -- сравнивает, насколько просели штуки (число покупателей)
      против денег: если штуки просели почти так же сильно, как выручка --
      это, скорее всего, нехватка трафика (проверить кассу/меню/зал,
      подумать про рекламу на этот день недели); если штуки почти по
      плану, а денег меньше -- скорее всего, просел средний чек (проверить
      скидки, допродажи, состав заказов);
    - отдельно смотрит, ГДЕ именно просело: если провал сосредоточен в
      1-2 конкретных часах (меньше 40% часов дня) -- предлагает разобрать
      именно эти часы (персонал, ассортимент, очередь); если просело
      почти весь день -- предлагает искать общую причину (погода,
      конкуренты, посещаемость района) и сверить с "Неделя к неделе" на
      Главной, тренд это или случайность одного дня.
- **"Топ товаров"** -- какие позиции меню и какие категории (не только
  кофе -- вся выпечка, десерты и т.д.) приносят больше всего выручки за
  выбранный период.

Почасовые данные и номер чека берутся из колонок "Hora de cierre" и
"Movimiento PDV" отчёта Wansoft -- они есть в каждой строке, отдельно
ничего выгружать не нужно. "Количество продаж" на "Главной" -- это
именно чеки (заказы), а не отдельные позиции: один заказ из трёх
круассанов считается одной продажей, не тремя.

**Важно для уже загруженных файлов:** старые загрузки (до этого
обновления) не содержат время и номер чека -- без них "Главная" и
"Продажи по часам" не заработают для тех дней. Чтобы это исправить --
один раз перезагрузи те же самые файлы через `Start.bat` -> пункт 1.
Дублей это не создаст (см. следующий раздел -- программа узнаёт уже
загруженные ЧЕКИ и переписывает их), но из-за дополнительного шага
загрузка в этот раз может занять чуть дольше обычного, особенно если
база в облаке.

## Почему одни и те же дни не задваиваются

Wansoft выгружает не по одному дню, а ДИАПАЗОНОМ дат, и диапазоны
обычно перекрываются: файл за 01.06-01.08 и файл за 01.08-15.09
содержат один и тот же первый августа. Имена у файлов при этом разные
(`...(1).xlsx`, `...(2).xlsx` и так далее).

Поэтому единица загрузки в программе -- **чек**, а не файл. Номер чека
(`Movimiento PDV`) сквозной: он не повторяется ни между точками, ни
между днями. Перед тем как вставить чек, программа удаляет все его
строки, если они уже есть в базе. Отсюда три полезных свойства:

- **Грузить можно что угодно и сколько угодно раз.** Перекрывающиеся
  диапазоны, повторная загрузка того же файла, файлы в любом порядке --
  результат всегда один и тот же.
- **Частичная выгрузка не затирает полный день.** Если выгрузку сделали
  днём, пока магазин ещё торговал, в файле будет только начало дня.
  Загрузка такого файла ПОСЛЕ полного заменит только те чеки, которые в
  нём есть -- остальные чеки дня останутся на месте.
- **Перезагрузка лечит уже задвоенные дни.** Обе копии чека удаляются,
  вставляется одна.

Раньше признаком "это уже загружено" было имя файла + номер строки --
у разных файлов они разные, поэтому перекрытие диапазонов ложилось в
базу дважды. Выручка за такой день удваивалась, а количество чеков
оставалось верным (оно и тогда считалось по уникальным номерам) --
поэтому в дашборде это выглядело не как ошибка, а как "средний чек
вдруг вырос вдвое".

Если база собиралась старой версией программы, такие дни в ней почти
наверняка есть. Для разовой уборки -- **дважды кликни `Cleanup.bat`**
(третья кнопка рядом со `Start.bat` и `Dashboard.bat`).

Он сначала ПОКАЗЫВАЕТ таблицу: какие дни затронуты, сколько чеков
задвоено, какая выручка за эти дни сейчас и какая станет после уборки.
И только потом спрашивает, удалять ли. Пока не нажмёшь Y и Enter, в базе
ничего не меняется -- любой другой ответ (или просто закрыть окно) всё
отменяет. Продажи при этом не теряются: у каждого чека остаётся ровно
одна полная копия, количество чеков не меняется вообще.

Работает и с локальным файлом, и с облачной базой -- с той, что указана
в `.env`, то есть ровно с той, которую показывает дашборд (он пишет это
в первых строках окна). После уборки нажми "🔄 Обновить данные" в
дашборде, иначе он до 5 минут будет показывать старые цифры.

Уборку достаточно сделать один раз: новые загрузки задвоения больше не
создают.

## Скорость: почему иногда нужно подождать, а иногда нет

В базе есть индексы по дате, точке и номеру чека -- это "оглавление",
по которому база находит нужный день, не перечитывая все строки подряд.
Создаются сами при запуске, в том числе на базе, собранной старой
версией программы; делать для этого ничего не нужно.

Поверх этого дашборд запоминает результат каждого запроса на 5 минут -- поэтому при
переключении фильтров (точка, диапазон дат, день) ответ обычно приходит
почти мгновенно, а не заново идёт в базу каждый раз (особенно заметно,
если база в облаке -- там каждый запрос идёт по интернету).

Из-за этого после перезагрузки файлов через `Start.bat` уже открытый
дашборд может до 5 минут показывать старые цифры. Чтобы не ждать --
кнопка **"🔄 Обновить данные"** внизу слева (под списком разделов)
сбрасывает память сразу. Страницу "Настройки" это не касается: там
список слов для кофе пересчитывается мгновенно после нажатия "Сохранить
список", как и раньше.

## Оформление

Дашборд оформлен в тёплой лесной палитре (глубокий зелёный фон, кремовый
текст, золото и тёмная бирюза для графиков и цифр) -- цвета настроены в
файле `.streamlit/config.toml` и подобраны так, чтобы:

- пара "золото / бирюза", которой рисуются два ряда на одном графике
  (например "% в деньгах" и "% в штуках", или "Факт" и "Типично"),
  оставалась различимой даже при дальтонизме -- проверено скриптом из
  скилла dataviz (валидатор проверяет контраст, светлоту, насыщенность и
  разницу цветов для разных типов цветовосприятия);
- всё было одинаково читаемо, если кто-то в настройках самого Streamlit
  переключит тему на светлую -- палитра проверена на обоих фонах сразу,
  отдельной "светлой" версии подбирать не пришлось.

Менять оформление можно только в двух местах: `.streamlit/config.toml`
(общий фон/акцент всего приложения) и константы `COLOR_PRIMARIO` /
`COLOR_SECUNDARIO` / `COLOR_TIPICO` / `_TEMA_GRAFICO` в начале
`dashboard.py` (цвета конкретных графиков) -- остальной код их не
трогает, так что дальше просто подставлять новые проверенные цвета.
